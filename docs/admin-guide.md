# Руководство администратора системы кафе
Версия документа: 0.1 | Версия системы: 2.3 | Дата: 21.10.2026

## 1. Назначение системы
Система автоматизации заказов: принимает заказы от клиентов, отправляет данные на кухню, интегрируется с платёжным шлюзом, формирует отчёты по продажам.

Состав узлов: клиентский терминал, сервер приложений Ubuntu 22.04, PostgreSQL 14, изолированный Docker-контейнер оплаты, MinIO хранилище изображений.

## 2. Установка
Предусловия: чистый сервер, Python 3.11, sudo-доступ.
1.  Клонировать репозиторий в `/opt/cafe-app`
2.  Создать виртуальное окружение, установить зависимости
3.  Применить миграции базы данных
4.  Запустить systemd-сервис
Ожидаемый результат: `systemctl status cafe-app` показывает active, `/health` возвращает 200 OK.
При неуспехе: просмотреть логи `journalctl -u cafe-app`.

## 3. Конфигурация (5 обязательных параметров)
1.  `DATABASE_URL`: подключение к БД, заглушка `postgresql://user:<DB_PASSWORD>@localhost/cafe`
2.  `PAYMENT_GATEWAY_URL`: адрес платёжного шлюза
3.  `STATIC_ROOT`: путь к статическим файлам
4.  `MAX_UPLOAD_SIZE`: лимит загрузки изображений 5 МБ
5.  `LOG_LEVEL`: уровень логирования INFO

## 4. Резервное копирование и откат
Ежедневно в 00:00 запускается `pg_dump`, архив сохраняется в `/var/backups/cafe-app`.
> **Внимание**: перед восстановлением обязательно остановить сервис, иначе база может повредиться.
> Откат приложения не откатывает схему базы данных — об этом нужно предупреждать администратора.

## 5. Диагностика (3 типовые ситуации)
1.  Страница меню не открывается: проверить статус сервиса и доступность сервера
2.  Заказы не доходят до кухни: проверить соединение приложения с базой данных
3.  Тестовый платёж отклонён: проверить срок действия `<PAYMENT_TOKEN>`
